# EXPERIENCE.md — Волейбол·Черкащина

Візуальна ідентичність — у `DESIGN.md`. Терміни — дослівно з
`../../../specs/spec-cherkasy-volley/glossary.md`. Обидва спайни перемагають будь-який мок.

## Foundation

- **Форм-фактор:** адаптивний веб (Next.js). Один застосунок, дві аудиторії:
  - **Глядач** — переважно телефон, лише перегляд, без акаунта. Публічні сторінки —
    mobile-first.
  - **Адмін** — переважно десктоп, введення даних. Форми працюють і на телефоні, але не
    оптимізуються під нього першочергово.
- **UI-система:** shadcn/ui на Tailwind (`[ПРИПУЩЕННЯ]`, див. DESIGN.md). EXPERIENCE.md
  задає лише поведінкову дельту.
- **Мова:** лише українська (`lang="uk"`). Часовий пояс відображення — `Europe/Kyiv`.
- **Модель доступу (зі спайну AD-6/AD-7):** редагують лише адміни; усе інше — публічне
  читання. Кнопок редагування для не-адміна не існує в DOM, не лише приховано.

## Information Architecture

Верхнє меню — три незалежні пункти: **Класичний** · **Пляжний** · **Архів**.

```
/                         → редірект на /classic
/classic                  Класичний: список активних турнірів + посилання в архів
/classic/[tournament]     Сторінка турніру, вкладки:
    ?tab=standings         Таблиця (за замовчуванням у стані Груповий етап+)
    ?tab=schedule          Розклад
    ?tab=teams             Команди (→ склад)
    ?tab=playoff           Плейоф (зʼявляється у стані Плейоф+)
/classic/[tournament]/teams/[team]   Склад команди
/beach                    Заглушка «Незабаром»
/archive                  Архів за роками
/archive/[year]/[tournament]         Архівний турнір — лише читання
/admin                    Панель адміна (лише роль Адмін):
    /admin/tournaments/new             Створити турнір
    /admin/tournaments/[t]              Ведення: команди, жеребкування, розклад,
                                       результати, плейоф, «завершити турнір»
    /admin/teams                        Довідник команд
    /admin/people                       Керування адмінами
/sign-in                  Вхід через Google
```

**Замикання поверхонь:** кожна можливість SPEC має поверхню, кожна поверхня — потік, що на
неї веде. CAP-1→`/sign-in`+`/admin/people`; CAP-2/3→`/admin/tournaments/*`;
CAP-4→`/admin/teams`+вкладка Команди; CAP-5→ведення турніру (жеребкування);
CAP-6→вкладка Розклад; CAP-7→екран матчу в адмінці; CAP-8→вкладка Таблиця;
CAP-9→вкладка Плейоф; CAP-10→`/archive/*`; CAP-11→усе публічне + меню.

## Voice and Tone

- Проста фактична українська. Без окличних знаків, без маркетингу.
- Терміни — дослівно з глосарія («Заявка команди», «Груповий етап», «Матч за 3-тє місце»).
- **Кнопки — дієслова:** «Створити турнір», «Заявити команду», «Провести жеребкування»,
  «Внести результат», «Сформувати плейоф», «Завершити турнір».
- **Порожні стани — один спокійний рядок:** «У розділі "Пляжний" ще немає турнірів.
  Незабаром.» / «Ще немає заявлених команд.» / «Результатів поки немає — таблиця зʼявиться
  після першого зіграного матчу.»
- **Підтвердження руйнівних дій — пряма мова:** «Видалити результат матчу? Таблиця
  перерахується.» / «Завершити турнір? Після цього результати редагувати не можна.»
- **Помилки — що сталось + що зробити:** «Не вдалося зберегти. Спробуйте ще раз.» /
  «Жеребкування недоступне: заявлено 7 команд із 10.»

## Component Patterns (поведінка)

- **Discipline nav** — стан активного пункту з `?tab` не змінюється; це справді різні
  розділи. Перемикання Класичний↔Пляжний — повний перехід сторінки.
- **Tab chip (всередині турніру)** — змінює `?tab` (shallow), стан вкладки в URL, щоб
  посилання на «Розклад» вело саме туди. Вкладка «Плейоф» прихована, поки турнір не в стані
  Плейоф+.
- **Standings table** — тільки читання для всіх (навіть адміна). Оновлюється при перезаході
  на сторінку після внесення результату (`revalidatePath`, спайн). Позиції 1–4 — синій
  жирний номер (`{components.standings-row-qualifying.marker}`); підказка при наведенні/тапі:
  «Виходить у плейоф».
- **Bracket** — тільки читання. Пара «очікує суперників» (`{components.bracket-pair-tbd}`)
  доки немає результатів обох півфіналів. Після внесення результату півфіналу відповідна
  пара фіналу/матчу за 3-тє місце заповнюється при наступному завантаженні.
- **Score input (адмін)** — поля рахунку по партіях; кількість за пресетом (до 5 /рівно 3).
  Валідація за правилами пресету перед збереженням; помилку показувати біля поля. Підсумок
  у партіях («3:1») рахується й показується поруч, не вводиться руками.
- **Match row (адмін)** — дія «Внести результат» / «Виправити». Значок `success` коли
  результат є. «Видалити результат» — під підтвердженням.
- **Admin action bar на сторінці турніру** — контекстні дії за станом: Чернетка →
  «Заявити команду», «Провести жеребкування»; Груповий етап → (жодної глобальної, лише
  введення результатів) + «Сформувати плейоф» коли всі групові матчі зіграно; Плейоф →
  «Завершити турнір» коли зіграно фінал і матч за 3-тє.

## State Patterns

| Стан | Поведінка |
|---|---|
| Завантаження | shadcn Skeleton у формі таблиці/картки; без спінерів на всю сторінку |
| Порожньо: немає турнірів | Порожній стан + (адміну) кнопка «Створити турнір» |
| Порожньо: немає команд | Порожній стан на вкладці Команди + (адміну) «Заявити команду» |
| Порожньо: немає результатів | Таблиця показує команди з нулями + рядок «Результатів поки немає» |
| Жеребкування не проведено | Вкладки Таблиця/Розклад показують «Групу буде сформовано після жеребкування» |
| Плейоф недоступний | Кнопка «Сформувати плейоф» неактивна + підпис «доступно коли всі матчі груп зіграно» |
| Матч без дати/часу | «час не визначено» (`{colors.muted-foreground}`) замість дати |
| Пара плейоф без суперників | «очікує суперників» у стилі `bracket-pair-tbd` |
| Турнір завершено | Банер «Турнір завершено» вгорі; усі дії редагування зникають; для адміна теж |
| Чернетка (глядач) | 404 — турнір не існує для не-адміна (ні в переліку, ні за прямим URL) |
| Помилка Server Action | shadcn Toast (`destructive`) з текстом; форма лишає введені дані |
| Не адмін відкрив /admin | Редірект на `/sign-in` (не ввійшов) або на головну з тостом «Потрібні права адміністратора» |

## Interaction Primitives

- **Вхід:** одна кнопка «Увійти через Google». Після входу — повернення на сторінку, з якої
  прийшов. Вихід — у меню користувача.
- **Редагування:** усі зміни синхронні (Server Actions зі спайну). Без оптимістичного UI —
  після успіху сторінка ревалідується, користувач бачить збережений стан. Кнопка на час
  запиту — `disabled` + Skeleton/спінер у кнопці.
- **Підтвердження:** руйнівні й незворотні дії (видалити результат, видалити турнір, зняти
  роль, завершити турнір) — shadcn `Dialog`, **не** нативний `confirm()` (архітектура:
  нативні діалоги блокують). Кнопка підтвердження — `destructive`.
- **Навігація після дії:** створення турніру → на сторінку турніру (Чернетка). Внесення
  результату → лишаємось на екрані матчу зі станом «збережено».
- **Зворотний звʼязок:** успіх — короткий Toast («Результат збережено»); стійкі зміни видно
  на самій сторінці.

## Accessibility Floor

- `lang="uk"` на `<html>`; усі інтерактивні елементи досяжні з клавіатури; видимий фокус
  (кільце `{colors.primary}`).
- Таблиці — семантичні: `<th scope="col">` для стовпців, `<caption>` з назвою групи;
  горизонтальний скрол таблиці має власний фокусований контейнер із `aria-label`.
- Ціль дотику ≥ 44×44px на мобільному (пункти меню, чипи вкладок, дії матчу).
- **Контраст:** синій `#1F6FEB` на білому ≈ 3.9:1 — достатньо для великого/жирного тексту й
  іконок, **недостатньо для основного тексту**. Посилання в тілі тексту — синій + підкреслення;
  дрібний синій текст не використовувати. Номери позицій 1–4 — жирні (проходять як «великий
  текст»).
- Стан («зіграно», «завершено», позиція плейоф) ніколи не передається лише кольором — завжди
  + текст або значок.
- Порожні стани й помилки — текстом, не лише ілюстрацією.

## Key Flows

### KF-1 — Олег веде чемпіонат (адмін, десктоп) · реалізує CAP-2…CAP-10

1. Олег входить через Google, відкриває `/admin/tournaments/new`, обирає тип «Чемпіонат»,
   систему очок «Класичний», 6 команд, 1 коло. Турнір створено у стані **Чернетка**.
2. На сторінці турніру заявляє 6 команд, у кожній додає гравців (мінімум — ПІБ).
3. Тисне **«Провести жеребкування»** — підтвердження — система формує групу й календар;
   стан → **Груповий етап**, зʼявляється вкладка Розклад із парами.
4. На вкладці Розклад проставляє дату/час/зал матчам.
5. Після кожного туру відкриває матч, вводить рахунок по партіях, зберігає. На вкладці
   Таблиця бачить перерахований порядок.
6. Коли всі матчі груп зіграно — кнопка **«Сформувати плейоф»** активується. **Климакс:**
   Олег її тисне — за секунду зʼявляється вкладка Плейоф із заповненими півфіналами
   (1–4, 2–3), фінал і матч за 3-тє місце — «очікує суперників».
7. Вносить результати півфіналів → фінал і матч за 3-тє наповнюються командами. Вносить їх
   результати. Тисне **«Завершити турнір»** (підтвердження про блокування редагування).
8. Турнір зникає зі списку активних і зʼявляється в `/archive/2026` з місцями 1–4.
   *Крайній випадок:* помилився в рахунку зіграного матчу → відкриває матч, «Виправити»,
   зберігає — таблиця (і, якщо зачеплено, сітка) перераховуються.

### KF-2 — Ірина перевіряє, коли грає син (глядач, телефон) · реалізує CAP-11, CAP-6, CAP-8

1. Ірина відкриває сайт з телефону — потрапляє на `/classic` зі списком активних турнірів.
2. Тапає «Юнаки і дівчата 2026» → сторінка турніру, вкладка Таблиця за замовчуванням.
3. Перемикає на вкладку **Розклад**, знаходить команду сина. **Климакс:** бачить картку
   наступного матчу — «субота, 11:00, СК "Спартак", суперник — команда з Умані».
4. Повертається на Таблицю — команда сина на 2-му місці, номер позиції синій (виходить у
   плейоф). Закриває вкладку. Акаунт не потрібен був жодного разу.

## Responsive & Platform

- **≥ 1024px:** контент у `{spacing.contentMaxWidth}` (1120px) по центру; таблиці й сітка
  повністю видимі; адмінські форми у дві колонки де доречно.
- **640–1023px:** одна колонка; таблиця вміщується або скролиться всередині контейнера.
- **< 640px:** меню дисциплін — компактна смуга (пункти в «⋯» за потреби); чипи вкладок
  скроляться горизонтально; таблиця скролиться всередині власного контейнера, `body` по
  горизонталі не рухається; картки сітки — стовпчиком.
- Друк/PDF, офлайн, нативні застосунки — поза обсягом (SPEC non-goals).
